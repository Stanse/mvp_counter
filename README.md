# RepCounter

Offline, on-device camera rep counter (Android). Full requirements: `REPCOUNTER_ANDROID.md`.
Architecture: `docs/ARCHITECTURE.md`. Non-obvious decisions: `docs/DECISIONS.md`.

Status: **M3 - signals and analyzers.** `:signals` (pose normalization + signal extraction),
`:analysis:api` (the `ThresholdAnalyzer` FSM archetype + `Gate`), `:analysis:strength`
(squat/pushup configs), `:analysis:jumprope` (`JumpRopeAnalyzer` + technique classification) and
`:capture`'s trace format are all implemented. `:tools:replay` runs the full pure-Kotlin pipeline
- `PoseFrame -> PoseNormalizer -> SignalExtractor -> Resampler -> ExerciseAnalyzer -> AnalyzerEvent`
- over the synthetic corpus in `testdata/traces/` and grades it against golden files
(`./gradlew :tools:replay:run`: `MAE = 0.0`, `microF1 = 1.0`). No camera, pose model, or Android
dependency anywhere in this path. Real capture (`CameraX`, `:pose:mediapipe`) lands in M4.

## Requirements

- JDK 17
- Android SDK with platform `36.1` **and** `37.1` installed (`sdkmanager "platforms;android-37.1"`),
  plus `local.properties` pointing `sdk.dir` at it (not committed - machine-specific)
- No Android emulator needed for anything except the (not-yet-written) instrumented tests in M6

## Build

```
./gradlew build
```

Runs `assemble` + `test` + `detekt`/`ktlint` + the pure-Kotlin module boundary check
(`verifyModuleBoundaries`) across every module. Everything currently passes without needing any
model file, emulator, or network access at build time.

## Test

```
./gradlew test                     # all JVM unit tests
./gradlew :core:dsp:test           # single module
```

**Level 1** (M2/M3): synthetic-signal unit tests in `:core:dsp`, `:signals`, `:analysis:api`,
`:analysis:jumprope` - known-frequency sines, optionally with seeded white noise and dropped
samples, checked against ground truth. See
`core/dsp/src/test/kotlin/dev/repcounter/core/dsp/synthetic/SyntheticSignals.kt` for the
generator and `docs/DECISIONS.md` for tuning notes (default thresholds, sign/lag conventions).

**Level 2** (M3): `:tools:replay`'s `ReplayCorpusTest` replays every trace in `testdata/traces/`
through the real pipeline and compares against its `.expected.json` golden - no Android, no
model, no emulator, fully deterministic. Run just this suite with
`./gradlew :tools:replay:test`, or get the human-readable CSV/metrics with
`./gradlew :tools:replay:run`. See `docs/DECISIONS.md`'s M3 section for how the goldens were
produced and verified.

Level 3 (instrumented video tests) lands in M6.

## Models

Bundled pose models are **not committed** (`app/src/main/assets/models/*.task`, `*.tflite` are
gitignored). Fetch them with:

```
./scripts/fetch_models.sh
```

This downloads MediaPipe's `pose_landmarker_lite.task` directly. The MoveNet
`movenet_singlepose_lightning_int8.tflite` fallback now lives behind a Kaggle API token (the old
`tfhub.dev` direct-download URLs are gone) - the script prints setup instructions if
`KAGGLE_USERNAME`/`KAGGLE_KEY` aren't set. The app runs fine on MediaPipe alone; MoveNet is an
optional runtime-switchable fallback (spec §12).

## Traces

`testdata/traces/` holds the synthetic jump-rope corpus: a `<name>.jsonl.gz` (gzipped JSON
Lines, spec §9 - one header line + one `PoseFrame` line per recorded frame) next to a
`<name>.expected.json` golden. Run the whole corpus through the pipeline and print per-trace and
aggregate metrics:

```
./gradlew :tools:replay:run
```

The synthetic traces themselves are generated by
`tools/replay/src/test/kotlin/dev/repcounter/tools/replay/fixtures/SyntheticTraceGenerator.kt`
and `GenerateFixturesTest` (disabled by default - it writes into the working tree, see its
KDoc). Recording a *real* on-device session trace (`TraceRecorder`) lands in M4.

## Module map

See `docs/ARCHITECTURE.md` for the full graph. Quick orientation: `:core:*`, `:signals`,
`:analysis:*`, `:pose:api`, `:capture`, `:tools:replay` are plain-JVM Kotlin (no Android SDK,
enforced by a Gradle check); `:pose:mediapipe`, `:pose:movenet`, `:data`, `:feature:workout`,
`:app` are Android modules.
